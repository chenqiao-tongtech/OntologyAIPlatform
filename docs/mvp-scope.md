# P1 MVP 范围定义

**文档路径：** `docs/product/mvp-scope.md`  
**产品：** P1 Ontology Engineering Platform  
**版本：** V1.0  
**日期：** 2026-11-21  
**状态：** 设计基线，待评审

## 1. 文档目的

定义 P1 首个最小可行产品（MVP）的目标、范围、用户、核心流程、功能边界和验收要求。

本文件用于控制首期研发范围，避免将长期产品愿景直接转化为首期开发任务。

## 2. MVP 产品目标

### 2.1 核心目标

验证本体作为工程资产的完整管理闭环：

**创建 → 编辑或导入 → 验证 → 版本化 → 导出。**

MVP 必须能够独立完成这一流程，不依赖尚未建设的 AI 发现引擎、复杂数据连接器或外部知识图谱数据库。

### 2.2 MVP 要验证的产品假设

| 编号 | 产品假设 | 验证方式 |
|---|---|---|
| H-01 | 用户需要集中管理本体项目 | 创建、查询、更新项目 |
| H-02 | 本体需要统一的数据模型 | 使用统一元模型创建和读取对象 |
| H-03 | 用户需要编辑或导入已有本体 | 完成模型创建、编辑和导入 |
| H-04 | 本体需要自动质量检查 | 执行结构和基础语义验证 |
| H-05 | 本体变更需要可追溯 | 创建快照并比较版本 |
| H-06 | 本体需要与外部工具互操作 | 导出并重新解析标准格式 |
| H-07 | 工程操作需要受控 | 权限检查和关键操作审计 |

## 3. MVP 目标用户

| 用户 | 主要任务 | MVP 所需能力 |
|---|---|---|
| 数据架构师 | 创建项目、组织模型 | 项目管理、本体管理 |
| 本体工程师 | 创建和维护本体 | 编辑、导入、验证、版本 |
| 领域专家 | 确认业务概念 | 查看模型、提供审核意见 |
| AI 应用开发者 | 使用已发布本体 | 查询版本、下载导出文件 |
| 平台管理员 | 管理访问和运行 | 用户权限、审计、任务状态 |

MVP 不要求实现完整多人实时协同，但应保留角色和权限扩展空间。

## 4. MVP 功能范围

### 4.1 P0：必须实现

#### A. 项目管理

- 创建项目；
- 查询项目列表和详情；
- 更新项目名称、描述和领域信息；
- 归档项目；
- 为项目生成稳定唯一 ID。

验收：项目创建后可通过 API 和 UI 查询；项目资源必须归属于明确项目。

#### B. 本体元模型与对象管理

至少支持：

- Ontology；
- OntologyClass；
- Property；
- Relation；
- Constraint；
- Term；
- OntologyVersion；
- ChangeRecord；
- ValidationRun；
- ValidationFinding。

对象应具备稳定 ID、类型、所属项目、必要的创建和更新时间等元数据。

验收：对象能够持久化、查询、更新；引用关系经过完整性检查。

#### C. 本体创建和编辑

- 创建本体；
- 创建、编辑和删除类；
- 创建、编辑和删除属性；
- 创建和编辑关系；
- 配置基本类型、定义域和值域；
- 查看本体对象详情；
- 保存编辑结果。

验收：编辑后的模型能够持久化，并可重新读取；非法引用不能进入正式模型状态。

#### D. 本体导入

首期选择明确支持的格式和子集，不承诺无条件兼容所有复杂 OWL 语法。

建议优先支持：

- RDF/Turtle；
- RDF/XML；
- JSON-LD（在选定支持范围内）。

验收：

- 成功导入的对象可以查询；
- 不支持或解析失败的内容提供明确错误；
- 导入失败不得留下半成品正式模型；
- 导入过程保留文件摘要、格式和操作记录。

#### E. 质量验证

至少包括：

**结构验证**

- 对象 ID 唯一性；
- 引用完整性；
- 必填字段；
- 对象类型合法性；
- 关系定义完整性。

**基础语义验证**

- 属性类型合法；
- 定义域和值域引用有效；
- 基础约束配置有效；
- 可配置的必需属性检查。

验收：验证结果形成 ValidationRun 和 Finding 记录，区分错误、警告和建议。

#### F. 版本管理

- 创建版本快照；
- 记录版本号和变更说明；
- 查询版本列表；
- 查询版本详情；
- 比较两个版本；
- 保护已创建快照不被普通编辑操作修改。

验收：版本快照创建后，其内容保持稳定；后续编辑不会改变历史版本内容。

#### G. 标准导出

- 导出约定支持的 RDF/OWL 格式；
- 导出平台约定的 JSON 表示；
- 记录导出格式、版本和时间；
- 导出后可通过相应解析器读取。

验收：对支持范围内的本体，导出后重新导入，关键对象和关系保持一致。

#### H. 基础权限与审计

- 用户身份识别；
- 项目级访问控制；
- 关键写操作权限检查；
- 创建、修改、删除、导入、验证、版本和导出等关键事件记录。

验收：无权限用户无法执行受保护操作；审计记录能够查询并关联具体对象。

### 4.2 P1：基础闭环后增强

- 数据库连接器；
- 数据库元数据采集；
- 文档元数据采集；
- 候选本体审核；
- 基础可视化建模；
- SHACL 验证能力增强；
- 完整发布管理；
- 本体关系图；
- 更细粒度的角色权限。

### 4.3 P2：后续产品能力

- 多源 AI 本体发现；
- 自动术语抽取；
- 类、属性和关系候选生成；
- 自动映射建议；
- 证据关联和冲突分析；
- 增量采集和变化检测；
- 高级概念合并；
- 实例知识图谱探索；
- 多环境发布；
- 高级多人协作；
- 自动化本体维护。

## 5. 明确不纳入 MVP 的内容

| 不纳入范围 | 原因 |
|---|---|
| 通用知识图谱数据库 | 超出本体工程资产管理的核心职责 |
| 完整企业数据治理平台 | 涉及数据质量、血缘、主数据等更大范围 |
| 完整 AI 本体自动发现系统 | 需要独立评估模型、证据和审核机制 |
| Agent 运行时控制平台 | 属于独立产品方向 |
| 生产业务授权引擎 | 不应由本体平台替代业务系统权限 |
| 通用工作流引擎 | 首期仅需有限的工程状态管理 |
| 大规模实例图谱分析 | 对首期本体工程闭环不是必要条件 |
| 多租户复杂计费 | 尚非 MVP 验证重点 |

## 6. MVP 核心用户流程

```text
用户登录
  |
  v
创建本体项目
  |
  v
创建本体 / 导入本体
  |
  v
编辑类、属性、关系和约束
  |
  v
执行质量验证
  |
  +---- 验证失败 ----> 查看问题并修复
  |                         |
  |                         +----> 重新验证
  |
  v
创建版本快照
  |
  v
比较版本（可选）
  |
  v
导出标准格式
  |
  v
重新解析并进行一致性检查
```

## 7. MVP 关键数据对象

| 对象 | 职责 |
|---|---|
| Project | 工程项目 |
| Ontology | 本体资产 |
| OntologyClass | 本体类 |
| Property | 属性 |
| Relation | 关系 |
| Constraint | 约束 |
| Term | 术语 |
| OntologyVersion | 版本快照 |
| ChangeRecord | 变更记录 |
| ValidationRun | 验证任务 |
| ValidationFinding | 验证问题 |
| AuditEvent | 审计事件 |
| ExportArtifact | 导出产物 |

实际数据库表结构可以按实现需要拆分或组合，但必须保证对象身份、版本归属和引用关系明确。

## 8. 非功能需求

| 编号 | 要求 | MVP 实施原则 |
|---|---|---|
| NFR-01 | 可扩展性 | 模块化设计，标准适配器接口 |
| NFR-02 | 可维护性 | 清晰分层、结构化日志、迁移脚本 |
| NFR-03 | 安全性 | 认证、项目权限、密钥保护、审计 |
| NFR-04 | 私有化部署 | 提供可重复容器化部署 |
| NFR-05 | 标准兼容 | 明确格式支持范围和映射规则 |
| NFR-06 | 可观测性 | 任务状态、错误和关键事件可查询 |
| NFR-07 | 可测试性 | 核心 API、模型和导入导出自动化测试 |
| NFR-08 | 数据完整性 | 外键、事务、快照一致性和唯一性约束 |

不在没有测试数据和环境的情况下预设性能指标。性能目标应在明确数据规模、并发模型和部署规格后制定。

## 9. 技术实现建议

MVP 建议采用模块化单体架构：

- 前端：React / Next.js / TypeScript；
- 后端：FastAPI / Python；
- 业务数据库：PostgreSQL；
- 文件存储：MinIO 或兼容 S3 的对象存储；
- 异步任务：Celery + Redis；
- RDF 处理：RDFLib；
- SHACL：pySHACL；
- 结构校验：JSON Schema；
- 图可视化：Cytoscape.js；
- 身份认证：可先采用平台基础认证，后续接入 OIDC / Keycloak。

首期不强制引入独立图数据库、向量数据库或 RDF 三元组存储。是否引入应由查询规模、数据形态和部署需求决定。

## 10. MVP 验收闸门

### Gate 1：项目与模型

- 项目可创建、查询和更新；
- 本体对象可创建和持久化；
- 核心引用完整。

### Gate 2：导入与编辑

- 支持格式能够成功导入；
- 编辑结果能够保存和重新读取；
- 错误输入能够得到明确反馈。

### Gate 3：质量验证

- 能发现约定的结构错误；
- 能执行基础语义规则；
- 验证报告可查询。

### Gate 4：版本管理

- 能创建稳定版本快照；
- 能查询和比较版本；
- 历史快照不受后续编辑影响。

### Gate 5：导出与安全

- 标准格式能够导出和重新解析；
- 项目权限有效；
- 关键操作具有审计记录；
- 部署文档和测试报告齐备。
